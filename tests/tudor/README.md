# tudor (web) tests

`tudor-v0_1.html` is system 2 of the owner's spec (`konzept_spezifikation_autonomes_feedback_system.md`): **David Tudor's no-input mixer**. The output of a mixer channel goes back into its own input, with no source at all; the noise of the electronics is the seed.
Loop: bus (return + hiss + kick) -> overdrive (soft clip between tanh and x / (1 + |x|), around a bias point: the only thing that limits the level) -> six resonators in parallel (band-pass filters at 55, 140, 350, 880, 2200, 5500 Hz, each with its own level; FOCUS = Q, TUNE moves all six) -> up to four allpass filters (the phase turn, faded in one by one) -> DC blocker -> return line with an adjustable loop gain (above about 1 at some resonance it sings by itself; POLARITY turns the return upside down).
Two channels (L, R) with their own hiss, tuned slightly apart (DETUNE) and fed a little from each other (LINK). LFO 1 moves the phase frequency, LFO 2 the tuning (both up to 1 kHz, per sample). The view shows how loud each resonator rings, the dominant pitch (zero crossings) and the clip activity.
Same shell as vink.loop, homoeo, chua (see `tests/feedbacks/README.md`); olive-green base colour. Silent until the first click; no input, no microphone.

**What the tests found while building:** the PHASE fader is not a gentle colour control: at high FOCUS a turned phase simply kills the loop (the filter can only make up a few degrees before the gain falls away), so some settings go quiet; the presets were chosen so that they sing, and the hint says so.
SHAPE 1 (x / (1 + |x|)) is mellower than tanh at the same drive (not brighter, as I first assumed); the hint now says "hard clip to soft bend". A loop that starts "by itself" at hiss 0 would still start from the numerical 1e-20 after about five seconds; the hint says "only a Kick does" and the test looks at the first two seconds only.
The output scale of the band-pass filters (k = 1 / Q) had to glide per sample, otherwise a FOCUS jump made a small step (R = 31 in the click test).

- `node tests/tudor/dsp.test.js` (about 3 minutes) - runs the AudioWorklet code of the page in Node: the loop starts from the hiss alone, stays quiet without hiss and kick, a Kick starts it, loop gain 0.5 dies out and 1.2 sings; every one of the six resonators alone rings at its note (55 ... 5500 Hz), TUNE x1.5 moves the note by 1.5; PHASE and POLARITY change the note; SHAPE 0 is brighter than 1; BIAS bounded; LEVEL, DETUNE (6 % apart, 0 = equal), TONE; reset (no click, starts again from the hiss); LFOs at slow and audio rate, depth 0 leaves the values alone; 24 corner and random settings at 44.1 / 48 / 96 kHz (no NaN, never above the level); everything open and closed again in one go; CPU.
- `PW=/opt/node22/lib/node_modules/playwright SHOTS=/tmp/shots node tests/feedbacks/browser.test.js tudor` - the shared browser test of the series plus the tudor parts: starts by itself, readout (pitch, clipping), mode bars drawn, preset "Whistle" moves the note above 1 kHz, polarity stored, loop gain lowest = quiet, Kick wakes it, reset starts again.
- `node tests/feedbacks/clicks.test.js tudor` - no clicks when a parameter changes while the sound runs (see `tests/feedbacks/README.md`). FOCUS and PHASE move only a little in this test (a wide filter or a turned phase lets the loop pick another note, which is a real change of sound and not a click); "all at once" uses a preset that keeps the loop alive.

**What this does not prove:** how it sounds (whether the loop is a pleasure or just harsh), Safari / iOS, the CPU load on a phone. Which note rings at a given PHASE depends on the filters: tuned by measurement, not by ear.
