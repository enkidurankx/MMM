# serge (web) tests

`serge-v0_3.html` is system 3 of the owner's spec (`konzept_spezifikation_autonomes_feedback_system.md`): **the Serge wave multiplier in a resonant loop**, built as an instrument you play (not a generative system). Four voices; each is a loop of four resonators (the body: string, pipe, plate, bell, glass; four modes at ratios of the key, BODY glides between the sets), a wave multiplier (sin(x) with up to four stages in a row: a level above 1 is folded back, so level becomes overtones) and the loop gain (the inverted attenuator), back into the resonators.
A struck key puts a short noise burst into the loop (STRIKE, COLOUR). Released, the loop gain is 1 - DAMP (below 1: it rings out like a bell); held, it is FOLD (above 1: it sings by itself, the more the harder it folds). ATTACK / RELEASE are how fast the loop gain moves between the two; HOLD is the sustain pedal.
STAGES / SPREAD / SKEW shape the folder (the curve is drawn live), POLARITY turns the odd modes of the body over, EDGE adds the raw folded wave to the resonator sound. Two LFOs up to 1 kHz (LFO 1: loop gain, LFO 2: pitch, so at audio rate it is FM). Keys: on-screen (touch, slide for glissando, higher on the key is louder), computer keyboard (A W S E D F ...; Z / X octave), MIDI in (notes, velocity, pitch bend, sustain pedal).
Same shell as the other feedback apps (see `tests/feedbacks/README.md`); teal base colour. Silent until the first key; no input, no microphone.

**What the tests found while building:** the loop gain and the first stage were the same knob (the threshold of singing moved with FOLD): the small-signal gain of the stages is now divided out, so 1 is always the threshold, and FOLD (while held) is boosted by the root of that gain, so more stages drive the loop harder. A held loop locks onto ONE mode of the body (a bell at FOLD x3 sings at 2.76 x the key and the fundamental is gone: the loop is a tuned oscillator whose pitch jumps between modes with FOLD and STAGES); the inharmonic mix of a bell is heard in the ring-out after a short strike with a fast RELEASE. A loop just under the threshold can hang on at -90 dB for ever through the tails of the other modes: voices below -80 dB after the key are cut. The polarity of the whole loop does nothing (a negative loop at the centre of a band-pass never oscillates), so POLARITY turns the odd modes over instead. A first version panned voice 0 almost fully to the right: peak 1.0 on one side and 0.36 on the other (equal-power pan law now).

- `node tests/serge/dsp.test.js` (about 3 minutes) - runs the AudioWorklet code of the page in Node: silent until a key; a held key sings (> -30 dB), released it rings out and dies, DAMP and RELEASE as set; pitch of five keys 36 ... 81 (whole multiples of the key, fundamental within 25 dB); body structure (bell at 2.76 x, string at whole multiples, pipe odd only, glass modes) by FFT; STAGES drive the loop harder, FOLD x8 is brighter than x1.3, SKEW adds even partials, POLARITY changes the spectrum; four voices, the fifth steals the oldest (bounded, no NaN), the same key again re-strikes; HOLD and its release; GLIDE; pitch bend +12 doubles the pitch; LEVEL, WIDTH, COLOUR; reset (no click); LFOs slow and at audio rate (FM sidebands at +- 200 Hz), 24 corner and random settings with five notes at 44.1 / 48 / 96 kHz; everything open and back; CPU (about 30 % of one core in Node with four voices and everything on).
- `PW=/opt/node22/lib/node_modules/playwright SHOTS=/tmp/shots node tests/feedbacks/browser.test.js serge` - the shared browser test of the series plus the serge parts: folder curve drawn, key A plays and names the note, release and die-away, touching and sliding on the keyboard, lifting the finger, octave buttons (stored), HOLD on / off, preset + Ping, reset.
- `node tests/feedbacks/clicks.test.js serge` - no clicks when a parameter changes while a note is held (see `tests/feedbacks/README.md`). Some parameters move only a little in this test (a harder loop locks to another mode: a real change of sound, not a click).

**What this does not prove:** how it sounds (whether the loop is a pleasure or just a sine that jumps), Safari / iOS, MIDI on a real device (the browser test has none), the CPU load on a phone. Which fold gives which mode is measured, not listened to.
